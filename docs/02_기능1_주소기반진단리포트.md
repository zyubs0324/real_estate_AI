# 기능 1 — 주소 기반 부동산 종합 진단 리포트

## 개요

주소를 입력하면 해당 물건에 적용되는 규제·정책·권리관계를 구조화된 리포트로 즉시 제공.
직방 지킴진단과 동일한 진단 구조를 공인중개사 업무에 최적화하여 구현.

## 입력 처리 — 주소 표준화 레이어 (필수)

모든 API 조회에 앞서 입력된 주소를 반드시 표준화한다.

**처리 흐름:**
```
사용자 입력 (도로명 또는 지번 주소)
    ↓
도로명주소 API (data.go.kr) 호출
    ↓
표준 도로명주소 + 지번주소 + 좌표(WGS84) 반환
    ↓
이후 모든 API 조회에 정규화된 값 사용
```

이 레이어 없이는 API마다 주소 형식이 달라 데이터 불일치가 발생한다.

## 진단 항목 A — 규제·정책 진단

| 항목 | 데이터 소스 | 수집 방법 | 난이도 |
|---|---|---|---|
| 토지거래허가구역 여부 | 국토부·서울시 고시문 | 자체 DB (폴리곤 매핑) | ⚠️ 중간 |
| 투기과열지구 여부 | 국토부 고시 | 자체 DB (행정구역 코드) | ⚠️ 중간 |
| 조정대상지역 여부 | 국토부 고시 | 자체 DB (행정구역 코드) | ⚠️ 중간 |
| 재개발·재건축 구역 여부 | 국토부·서울시 도시계획포털 | 크롤링 + 자체 DB | ⚠️ 중간 |
| 용도지역·지구·구역 | VWorld API | REST API 실시간 조회 | ✅ 쉬움 |
| 개별공시지가 | VWorld API | REST API 실시간 조회 | ✅ 쉬움 |

**규제지역 DB 구축 방식:**
- 토지거래허가구역:
  - 데이터 확보: 서울시 열린데이터광장(data.seoul.go.kr)에서 GeoJSON 다운로드
  - MVP: GeoJSON을 정적 파일(`/data/land_transaction_zones.json`)로 관리
  - 판별 방식: ray casting 알고리즘 (`lib/regulations.ts`) — 입력 좌표가 폴리곤 내부인지 판별
  - 추후: PostGIS(`st_contains`)로 DB 테이블 이전
- 투기과열지구·조정대상지역: 행정구역(시·군·구) 코드 기준으로 시드 SQL(`supabase/seed_regulations.sql`) 관리, 고시 시 수동 업데이트

## 빠른 확인 (Quick Check) — 기본 동작

전체 진단 리포트(A~G 전 항목) 실행 전에, 핵심 위험 항목만 먼저 빠르게 조회하는 경량 모드.

**특징:**
- 미등록 매물 포함 모든 주소에서 사용 가능
- 호출 API: 건축물대장(위반건축물) + 등기부(근저당·압류·경매·가처분·신탁·임차권등기) + 규제지역 내부 DB
- API 2~3건, 2~3초 내 결과 표시
- 전체 진단 대비 속도 5~10배, 비용 1/5 수준

**자동 실행 시점 및 흐름:**
1. 매물 등록 완료 → `/api/quick-check` POST 비동기 호출 (Next.js API Route)
2. 건축물대장 + 등기부 + 규제지역 3개 API 병렬 호출
3. 결과를 `property_diagnostics` 테이블에 저장 (캐싱)
4. 전체 매물 리스트에서 위험 태그 즉시 표시 (중개사 별도 실행 불필요)

**재진단 트리거 정책:**
- 신규 등록 시: 1회 자동 실행
- 정기 재진단: admin 설정 화면에서 주기 설정 (권장: 월 1회)
- 수동 재진단: 리포트 화면 [재진단] 버튼

**property_diagnostics 캐싱 위험 플래그 목록:**
```
has_violation_building   -- 위반건축물
has_mortgage             -- 근저당
has_seizure              -- 압류·가압류
has_auction              -- 경매
has_trust                -- 신탁
has_lease_registration   -- 임차권등기명령
has_injunction           -- 처분금지가처분 (가처분)
is_land_transaction_zone -- 토지거래허가구역
is_speculation_zone      -- 투기과열지구
is_adjustment_zone       -- 조정대상지역
is_redevelopment_zone    -- 재개발·재건축 구역
diagnosed_at             -- 마지막 진단 일시
```

> **토지별도등기**: Quick Check 캐시 플래그에는 포함되지 않음. 전체 진단 리포트(등기부 풀 파싱) 실행 시 항목 B에서 확인. Quick Check는 주요 위험 항목(근저당·압류·경매 등) 위주로 제한하여 속도를 최우선으로 한다.

**결과 표시:**
- 위험 항목 있음: 해당 태그 표시 (`위반` `근저당` `압류` `경매` `토지거래허가구역` 등)
- 전체 진단 없음: [전체 진단 리포트 보기] 버튼으로 연결

**등기부 API 정책:**
- 등기정보광장 API(무료, 1,000건/일 한도) 우선 사용
- 한도 초과 또는 상세 데이터 필요 시 CODEF API 전환 (건당 50~100원)

## 리포트 구성 순서 (UI)

1. 주소 입력 → 표준화 처리
2. 빠른 확인 결과 표시 (위험 태그) → [전체 진단 리포트 보기] 버튼
3. 전체 진단 실행 시: 섹션별 진단 결과 카드 (A~G)
4. 종합 위험도 요약 (AI 의견 — GitHub Models gpt-4o, Phase 4 U4-3 활성화)
5. 맞춤 특약 목록
6. 리포트 PDF 출력 버튼 (Phase 5)

## 리포트 필수 고지 문구

> **이 리포트는 공개된 공공 데이터를 기반으로 생성되었습니다.**
> 확정일자를 받은 선순위 임차인은 등기부에 표시되지 않아 이 리포트로 확인할 수 없습니다.
> 실제 계약 전 임대차 현황 확인서를 발급받거나 임대인에게 직접 확인하시기 바랍니다.
> 이 리포트는 법적 효력이 없으며, 투자·계약 결정의 근거로 단독 사용하지 마십시오.
