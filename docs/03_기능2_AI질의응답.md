# 기능 2 — 부동산 특화 AI 질의응답

> **구현 상태**: Phase 4 (U4-1 ~ U4-3) — GitHub Models 무료 API 사용으로 즉시 구현 가능

## 개요

자연어로 복잡한 부동산 관련 질문을 입력하면, 법령·판례·보도자료·고시 등 공공 데이터를 근거로 출처를 명시한 답변을 제공하는 RAG(Retrieval-Augmented Generation) 기반 AI 질의응답 시스템.

---

## AI 모델 스택 (GitHub Models)

> **Base URL**: `https://models.inference.ai.azure.com`
> **인증**: `Authorization: Bearer ${GITHUB_TOKEN}`
> **SDK**: `openai` npm 패키지 (`baseURL` 오버라이드)

| 용도 | 모델명 | 이유 |
|---|---|---|
| AI 질의응답 (RAG Chat) | `gpt-4o` | 한국어 법률 문서 이해 최상, 128K 컨텍스트 |
| 임베딩 (RAG 벡터화) | `Cohere-embed-v3-multilingual` | 한국어 포함 다국어 명시 지원, 1024차원 |
| 가벼운 요약·분류 | `gpt-4o-mini` | 비용 효율 (단순 태스크용) |

**클라이언트 초기화 (`lib/github-ai.ts`):**

## 기술 구조 — RAG 아키텍처

```
[데이터 수집 파이프라인]
법령·판례·보도자료·고시
    ↓
텍스트 추출 → 청크(chunk) 분할 (500토큰 단위)
    ↓
Cohere-embed-v3-multilingual 임베딩 생성
    ↓
Supabase pgvector에 저장 (1024차원 벡터)

[질의응답 처리]
사용자 자연어 질문
    ↓ (선택) 특정 매물 선택 시 CRM 데이터 추가
Cohere-embed-v3-multilingual 임베딩 변환
    ↓
pgvector에서 유사 문서 검색 (코사인 유사도, top-5)
    ↓
검색된 문서 + 질문 + (CRM 컨텍스트) → gpt-4o 전달
    ↓
AI 답변 스트리밍 생성 + 출처(법령명·조항·판례번호) 표시
```

**구현 파일:**
- `lib/github-ai.ts` — AI 클라이언트 초기화
- `lib/rag.ts` — RAG 파이프라인 (임베딩 검색 + gpt-4o 호출)
- `scripts/embed_laws.ts` — 법령 데이터 일괄 임베딩 스크립트 (Node.js CLI)
- `app/api/chat/route.ts` — 질의응답 API 엔드포인트 (스트리밍)

## 데이터 소스 및 수집 방법

| 데이터 | 출처 | 수집 방법 | 업데이트 주기 |
|---|---|---|---|
| 법령 원문 | 법제처 open.law.go.kr | API 실시간 연동 | 개정 시 자동 |
| 판례 | 법제처 판례 API | API 배치 수집 (상급심 위주) | 주기적 배치 |
| 국토부 보도자료·고시 | 국토교통부 홈페이지 | 웹 크롤링 + 색인 | 일 1회 |
| 서울시 도시계획 고시 | 서울시 도시계획포털 | 웹 크롤링 + 색인 | 일 1회 |
| 국세청 유권해석·예규 | 국세청 홈페이지 | 웹 크롤링 + 색인 | 주 1회 |
| 공인중개사 관련 지침 | 한국공인중개사협회, 국토부 | 직접 수집 후 저장 | 수동 |

### 부동산 특화 추가 데이터

- 규제지역 지정·해제 이력 (투기과열지구·조정대상지역)
- 재개발·재건축 고시 (신속통합기획, 공공재개발)
- 주택공급 관련 보도자료 (분양가상한제, 청약 제도)
- 양도세·취득세·종부세 예규·유권해석 (국세청 훈령)

## 내부 CRM 데이터 연동 범위

기본 질의응답은 외부 공공 데이터만 사용한다. 특정 매물을 선택하면 내부 데이터를 컨텍스트에 추가할 수 있다.

| 컨텍스트 유형 | 포함 데이터 | 예시 활용 |
|---|---|---|
| 기본 (외부 공공 데이터만) | 법령·판례·보도자료 | "계약갱신청구권 행사 기한은?" |
| 매물 선택 시 추가 | 해당 주소 거래 이력, 등록 인물, 메모 | "이 매물 임차인이 갱신청구권 썼나?" |
| 메모 포함 여부 | 사용자가 포함/제외 선택 | 민감한 현장 정보는 선택적으로 포함 |
| 사후관리 연동 | property_maintenance 시설이력 선택 | "이 보일러 수리 건 보증 기간 지났나?" |

> 내부 데이터를 AI에 전달할 때는 GitHub Models API의 context window 내에서만 처리되며, 외부에 저장·전송되지 않는다.

## 사후관리 AI 법률 조언 연동

`/properties/[id]` → 시설이력(Maintenance) 탭에서 빠른 질의 버튼 제공:

- [AI에게 묻기] 버튼 클릭 → `/ai-chat?context=maintenance&id={maintenanceId}`로 이동
- 해당 시설이력 내용(하자 설명, 수리 내역, 날짜) 자동 컨텍스트 주입
- "이 하자 책임은 임대인/임차인 중 누구에게?" 형태의 사전 질문 템플릿 제공

## 데이터 수집 도구 (관리자 기능)

자동 크롤러 외에 수동으로 데이터를 보완할 수 있는 도구.

### URL 즉시 크롤링 (3-A)

- 관리자 화면에서 URL 입력
- 입력 즉시 해당 페이지 크롤링 → 텍스트 추출 → pgvector 임베딩 저장
- 색인 완료 상태 표시 (성공/실패/진행중)

### 직접 입력 (3-B)

- 법령·판례·보도자료 유형별 입력 폼
- 제목, 본문, 출처, 날짜, 유형 태그를 직접 입력
- 저장 즉시 벡터 임베딩 생성 및 색인

## 벡터 DB 설계 (pgvector)

**`documents` 테이블:**

| 필드 | 내용 |
|---|---|
| id | UUID |
| type | law(법령) / case(판례) / press(보도자료) / notice(고시) / manual(직접입력) |
| title | 문서 제목 |
| content | 원문 텍스트 (청크 단위, 500토큰) |
| source | 출처 (법령명, 판례번호, URL 등) |
| source_date | 원본 문서 날짜 |
| embedding | vector(1024) — Cohere-embed-v3-multilingual 출력 차원 |
| created_at | 색인 일시 |

**검색 쿼리 예시:**
```sql
SELECT content, source, 1 - (embedding <=> query_embedding) AS similarity
FROM documents
ORDER BY embedding <=> query_embedding
LIMIT 5;
```

## 답변 원칙

1. **출처 명시** — 법령명 + 조항 번호 + 판례번호를 답변 하단에 표시
2. **법적 고지** — "이 답변은 법률 자문이 아닙니다" 문구 모든 답변에 포함
3. **전문가 연결** — 복잡한 세무·법률 사안은 세무사·변호사 상담 권고
4. **불확실성 표현** — 근거 문서가 없으면 "관련 데이터 없음"으로 명시, 추측 금지

## UI 구성

- 질문 입력창 + 매물 선택 (선택적) + 메모 포함 여부 토글
- 답변 영역: 본문 스트리밍 + 출처 목록 + 법적 고지
- 대화 이력: 세션 내 이전 질문·답변 유지
- 출처 클릭 시 원본 문서 링크 이동 (가능한 경우)
- 사후관리 탭에서 진입 시 컨텍스트 자동 주입 배너 표시
