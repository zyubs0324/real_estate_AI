# 기술 스택 — 결정 및 근거

## 핵심 스택

| 역할 | 기술 | 선택 이유 |
|---|---|---|
| 프레임워크 | **Next.js (TypeScript)** | 프론트+백엔드를 하나의 프로젝트로, Vercel 배포와 궁합 최적, Claude Code와 호환성 최고 |
| 데이터베이스 | **Supabase (PostgreSQL)** | 관리형 서비스로 설치 불필요, 웹 UI로 데이터 직접 확인 가능, 무료 플랜 제공 |
| 벡터 DB | **pgvector** (Supabase 내장) | 별도 벡터 DB 서비스 불필요, Supabase 프로젝트 내에서 바로 활성화 |
| 인증 | **Supabase Auth** | 이메일 로그인 기본 제공, RLS(Row Level Security)로 테넌트 분리 |
| 스토리지 | **Supabase Storage** | 계약서 파일(PDF/HWP) 보관, 접근 권한 연동 |
| AI 모델 | **GitHub Models** (gpt-4o, Cohere-embed-v3-multilingual) | 무료, 한국어 법령 RAG 최적, openai SDK 호환 |
| 배포 | **Vercel** | Next.js 원클릭 배포, 환경 변수 관리, 무료 플랜 |
| IDE | **Cursor** | 바이브 코딩 최적 IDE, Claude Code와 연동 |
| AI 코딩 | **Claude Code** | Cursor 터미널에서 실행, 비개발자 코딩 지원 |
| 크롤링 | **Cheerio** (정적) + **Playwright** (동적) | Node.js 기반으로 TypeScript 생태계 유지, 정부 사이트 대응 |
| 이메일 발송 | **Resend** | Next.js/Vercel 생태계 최적, 무료 플랜 3,000건/월 |
| 문자(SMS) 발송 | **솔라피(Solapi)** | SMS·LMS·카카오 알림톡 단일 API, 추후 카카오 알림톡 확장 가능 |
| **디자인 시스템** | **Apple 디자인 언어** + **Pretendard** | `docs/apple.md` 공식 채택. Tailwind `tailwind.config.ts`에서 Apple System Colors(`#0071e3`, `#34c759`, `#ff9f0a`, `#ff3b30`) 커스텀 색상 등록, `font-family: 'Pretendard'` 기본 폰트 설정 |

## 스택 선택 배경

### Next.js를 선택한 이유

- 프론트엔드(React)와 백엔드(API Routes)를 하나의 프로젝트에서 관리
- Vercel과 완벽한 통합으로 배포 복잡성 최소화
- Claude Code가 Next.js 프로젝트 구조를 가장 잘 이해함
- TypeScript 기본 지원으로 타입 안전성 확보

### Supabase를 선택한 이유

- PostgreSQL 기반으로 관계형 데이터 모델 완전 지원
- pgvector 내장으로 벡터 검색과 관계형 데이터를 단일 DB에서 처리
- Supabase Auth + RLS로 사무소별 데이터 격리 (Row Level Security)
- 웹 대시보드에서 SQL 쿼리 직접 실행 가능 → 비개발자도 데이터 확인 용이
- Storage로 계약서 파일 보관, 접근 권한 연동

### GitHub Models를 선택한 이유

- GitHub Personal Access Token으로 즉시 무료 사용 (별도 계약·결제 없음)
- `openai` npm 패키지 + `baseURL` 오버라이드만으로 즉시 연동 (OpenAI 호환 API)
- `gpt-4o`: 한국어 법령·판례 텍스트 이해도 최고, 128K 컨텍스트
- `Cohere-embed-v3-multilingual`: 한국어 포함 다국어 임베딩 명시 지원 (1024차원)
- RAG 답변 생성, 진단 리포트 종합 의견, 특약 문구 생성 모두 단일 클라이언트(`lib/github-ai.ts`)로 처리

## DB 스키마 핵심 테이블

```sql
-- 사무소 구성원 (Supabase Auth 연동)
-- settings JSONB로 사용자별 개별 설정 관리 (스키마 변경 없이 항목 추가 가능)
-- is_admin: admin 전용 기능(구성원 초대·권한 설정·전체 설정) 분기용. RLS 정책 적용.
users: id, 이름, 이메일, 역할(admin/member/assistant), 사무소명,
       is_admin(boolean, default false),
       settings JSONB default '{
         "lease_countdown_days": 100,
         "auto_priority_enabled": true,
         "auto_priority_days": 30,
         "external_notify_default": false,
         "external_notify_channels": ["email"],
         "notify_deadline_enabled": true,
         "notify_schedule_enabled": true,
         "notify_regulation_change_enabled": true,
         "notify_diagnosis_change_enabled": true,
         "notify_maintenance_recovery_enabled": true,
         "notify_maintenance_recovery_days": 7,
         "notify_commission_unpaid_enabled": true,
         "notify_commission_unpaid_days": 30
       }'
-- lease_countdown_days                 : 임대 만료 카운트다운 표시 시작일 (기본 100일 전)
-- auto_priority_enabled                : 만료 임박 시 집중 관리 자동 지정 활성 여부 (기본 true)
-- auto_priority_days                   : 집중 관리 자동 지정 기준일 (기본 30일 이내 진입 시)
-- external_notify_default              : 일정 등록 시 외부 당사자 알림 기본값 (기본 false)
-- external_notify_channels             : 외부 알림 발송 채널 기본값 ["email"] / ["sms"] / ["email","sms"]
--   이메일: people.이메일 보유 시 발송 / 문자: people.전화번호 보유 시 발송
-- ── 알림 자동화 설정 (모두 기본 활성, 사용자가 설정 페이지에서 개별 비활성 가능) ──
-- notify_deadline_enabled              : 거래 기한 알림 (거래신고·계약만료·갱신청구권) 기본 true
-- notify_schedule_enabled              : 일정 D-1 알림 기본 true
-- notify_regulation_change_enabled     : 규제지역 변경 시 담당 매물 알림 기본 true
-- notify_diagnosis_change_enabled      : 진단 재실행 후 위험 항목 변경 시 알림 기본 true
-- notify_maintenance_recovery_enabled  : 사후관리 대납 미회수 알림 기본 true
-- notify_maintenance_recovery_days     : 대납 후 N일 경과 시 알림 (기본 7일)
-- notify_commission_unpaid_enabled     : 수수료 미수령 알림 기본 true
-- notify_commission_unpaid_days        : 잔금완료 후 N일 경과 시 수수료 미수령 알림 (기본 30일)

-- 타부동산 사무소 (공동중개 파트너 또는 외부 매물 등록 업체)
-- 매물을 직접 소유자에게 받지 못하고 타부동산을 통해야 할 때 연락처·이력 관리
-- 소속 구성원: people.agency_id → agencies 로 연결
-- 공동중개 거래: transactions.co_agency_id → agencies 로 연결
-- 외부 수집 매물 등록 업체: properties.listing_agency_id → agencies 로 연결
agencies: id(UUID),
          name(text),                      -- 상호명 (예: 옥수 한강공인중개사)
          representative(text, nullable),   -- 대표 공인중개사명
          phone(text, nullable),            -- 대표 전화번호
          address(text, nullable),          -- 사무소 주소
          license_no(text, nullable),       -- 중개사무소 등록번호 (선택)
          notes(text, nullable),            -- 특이사항 메모
          created_by(FK → users),
          created_at(timestamp)

-- 인물
-- email: 외부 당사자 일정 알림 발송용. 수집 가능한 경우에만 입력.
-- agency_id: 타부동산 소속인 경우 해당 agencies FK (null이면 일반 개인)
-- agency_role: 타부동산에서의 역할 — 대표중개사 / 소속중개사 / 중개보조원
people: id(UUID), 이름, 전화번호(nullable), 이메일(nullable),
        생년도(nullable), 별칭(nullable),
        user_id(nullable FK → users),
        agency_id(nullable FK → agencies),   -- 타부동산 소속인 경우
        agency_role(text, nullable)           -- 대표중개사 / 소속중개사 / 중개보조원

-- 선택값 관리 (admin이 추가·활성/비활성 가능한 드롭다운 옵션 통합 테이블)
-- category 예시: 'building_type' (건물 유형) — 향후 추가 선택 필드도 동일 테이블 사용
-- 기본 building_type 값: 아파트, 오피스텔, 다세대주택, 연립주택, 단독주택, 상가, 사무실, 기타
-- is_active=false: UI 드롭다운에서 숨김 처리 (기존 데이터는 보존)
lookup_codes: id(UUID),
              category(text),              -- 'building_type' 등 필드 식별자
              value(text),                 -- DB 저장값 (예: '아파트')
              label(text),                 -- UI 표시 레이블 (value와 동일하거나 다를 수 있음)
              sort_order(integer),         -- 표시 순서
              is_active(boolean, default true),
              created_by(FK → users, nullable)  -- null = 시스템 기본값

-- 주소지(매물)
-- 라벨 3개는 중복 적용 가능 (예: 우리매물 + 집중관리 동시)
-- building_type: lookup_codes(category='building_type').value 참조, Quick Check 시 건축물대장에서 자동 채움
-- source_url: 외부 플랫폼(네이버 부동산 등) 원본 링크 보관용 (관심 매물 빠른 등록 시 활용)
-- external_ids: 외부 플랫폼 매물 고유 ID 맵 (JSONB). 멀티 플랫폼 중복 방지 키.
--   플랫폼별 추출 ID: naver(articleNo), zigbang(areaHoId), dabang(detail_id), peterpan(경로 ID), sheet(행 식별자)
--   예: {"naver": "2621161705", "zigbang": "919861", "dabang": "69e1b72...", "peterpan": "19147270"}
--   구글 시트 동기화 매물: {"sheet": "row:42"} 또는 {"sheet": "옥수삼성 102동 302호"} 형태
--   복수 플랫폼 동시 등록 가능: {"naver": "2621161705", "zigbang": "919861"} — 병합 선택 시
--   중복 체크: external_ids ? 'naver' (PostgreSQL JSONB 키 존재 확인 연산자)
--   플랫폼별 조회: external_ids ? 'platform' (특정 플랫폼에 등록된 매물)
--   우리 매물 조회: is_our_property = true (외부 플랫폼 동시 등록 여부 무관)
--   직접 등록 매물 (외부 플랫폼 없음): external_ids = '{}'
--   주소 기반 교차 플랫폼 중복 체크: (도로명주소 + 호수) 일치 시 병합/신규 선택 제공
-- listing_agency_id: 외부 수집 매물을 플랫폼에 등록한 타부동산 FK (우리 매물은 null)
-- listing_agent_id: 해당 타부동산의 담당 직원 FK (people.agency_id = listing_agency_id 인 인물)
properties: id(UUID), 도로명주소, 지번주소, 건물명, 동, 호수,
            building_type(text, nullable),              -- 건물 유형 (lookup_codes 참조)
            source_url(text, nullable),                 -- 최근 등록에 사용한 외부 링크
            external_ids(JSONB, default '{}'),          -- 플랫폼별 고유 ID 맵 (중복 방지)
            listing_agency_id(nullable FK → agencies),  -- 외부 수집 매물의 등록 타부동산
            listing_agent_id(nullable FK → people),     -- 해당 타부동산 담당 직원
            status(공실/임대중/매매완료/중개진행중), assigned_user_id(FK → users),
            is_our_property(boolean, default false),    -- 우리 매물
            is_watchlist(boolean, default false),       -- 관심 매물
            is_priority(boolean, default false)         -- 집중 관리

-- 인물-주소지 역할 이력
relations: id, person_id(FK), property_id(FK), 역할, 시작일, 종료일(null=현재)

-- 시설 관리 이력 (사후관리 + 마케팅 자산 통합 테이블)
-- 세 가지 용도로 사용:
--   1. 사후관리: 임차인 고장 신고 → 처리 과정·결과 기록
--   2. 비용 대납·회수 추적: 중개사 또는 임차인이 먼저 지불한 경우 채권 관리
--   3. 마케팅 자산: 교체 완료된 시설을 다음 임대 시 강점으로 노출
--
-- type: 수리요청(임차인 신고 → 진행) / 시설교체(완료 사실 직접 등록) / 정기점검 / 기타
-- category: 보일러·샤시·도배·장판·전기·수도·에어컨·외벽·기타 (자유 입력)
-- is_replacement: true=교체(새것) / false=수리 — 교체만 마케팅 자산 가능
-- replacement_date: 교체 완료일 → "N년 경과" 자동 계산 기준
-- is_marketing_asset: 다음 임대 매물 상세에 노출할 항목 여부
-- paid_by: 최종 비용 부담 주체 (임대인 부담 원칙 — 민법 제623조)
--
-- ── 비용 대납·회수 필드 ──────────────────────────────────────────

--   기타    : 위 유형에 해당하지 않는 일정
schedules: id(UUID), transaction_id(FK, nullable), property_id(FK, nullable),
           type(임장/사전미팅/계약/잔금/기타),
           scheduled_at(timestamp),
           location(text, nullable),
           status(예정/완료/취소),
           external_notify_enabled(boolean, default false),
           external_notify_channels(JSONB, default '["email"]'),  -- 일정별 채널 오버라이드
           memo(text, nullable),
           created_by(FK → users)

-- 일정 참석자 (내부 구성원 + 외부 인물 모두 등록 가능)
schedule_participants: schedule_id(FK), person_id(FK, nullable),
                       user_id(FK, nullable)

-- 임장 일정 ↔ 매물 다대다 연결 (임장 1회에 복수 매물 확인 시)
-- schedules.property_id(단일 FK): 단독 임장·빠른 등록용으로 유지 (하위호환)
-- schedule_properties: 한 임장에서 여러 매물을 확인했을 때 전체 목록 관리
--   운용 방식: schedules.property_id=첫 번째 매물 + 나머지 매물을 schedule_properties에 추가
--   또는: schedules.property_id=null + 전체를 schedule_properties에만 등록
--   임장 상세 화면에서 schedule_properties 전체를 "연결 매물" 섹션으로 표시
schedule_properties: schedule_id(FK → schedules),
                     property_id(FK → properties),
                     PRIMARY KEY (schedule_id, property_id)

-- 매물별 접근 권한
property_permissions: property_id(FK), user_id(FK), 권한레벨

-- 분쟁 이력
-- 계약파기·배액배상·보증금반환 등 금전 분쟁을 구조화하여 추적
-- principle_amount: 원칙상 받아야 할 금액 (예: 배액배상 3,000만원)
-- settled_amount: 실제 합의·지급된 금액 (예: 원금만 반환 1,500만원)
-- timeline: JSONB 배열 [{date, content, created_by}] — 협의 과정 시계열 기록
-- initiated_by: 분쟁을 일으킨 당사자 (person_id)
disputes: id(UUID), transaction_id(FK),
          type(계약파기/배액배상분쟁/보증금반환분쟁/기타),
          initiated_by(person_id FK),          -- 분쟁 유발 당사자
          principle_amount(numeric, nullable), -- 원칙 금액
          settled_amount(numeric, nullable),   -- 실제 합의 금액
          status(협의중/합의완료/소송진행중/종결),
          timeline(JSONB, default '[]'),        -- 협의 과정 시계열
          resolved_at(timestamp, nullable),
          created_by(FK → users)

-- 메모
-- type: normal(일반) / warning(주의 — 인물 프로필에 빨간 배지 표시) / dispute(분쟁 관련)
-- warning 메모는 people에 연결 시 인물 검색·상세에서 건수 즉시 노출
-- agency_id: 타부동산 사무소 단위 메모 (파일 첨부·공개범위 포함, agencies.notes 단순 텍스트보다 풍부)
--   예: "하이부동산 — 소장 수수료 협상 까다로움, 2025.03 분쟁 전력 있음" + 관련 문서 첨부
memos: id, content, type(normal/warning/dispute, default normal),
       property_id(nullable FK), person_id(nullable FK),
       transaction_id(nullable FK), dispute_id(nullable FK),
       agency_id(nullable FK → agencies),   -- 타부동산 단위 메모
       visibility(private/office), created_by(FK → users)

-- 사무소 중개수수료 요율 설정 (전체 설정 — admin 관리)
-- 거래 유형·금액 구간별 상한 요율 테이블. 정부 고시 변경 시 새 레코드 추가(이력 보존).
-- effective_from: 적용 시작일 → 거래 계약일 기준으로 당시 유효 요율 자동 선택
-- max_amount: 해당 구간 한도액 (예: 5천만원 미만 매매 → 25만원 한도)
-- 현행 법정 상한요율 기본값 (2021년 기준):
--   매매: 5천만원미만 0.6%(25만), 5천~2억 0.5%(80만), 2~6억 0.4%, 6~9억 0.5%(협의), 9억↑ 0.9%(협의)
--   임대차: 5천만원미만 0.5%(20만), 5천~1억 0.4%(30만), 1~3억 0.3%, 3~6억 0.4%(협의), 6억↑ 0.8%(협의)
commission_rate_settings: id(UUID),
                          transaction_type(매매/전세/월세),
                          price_from(numeric),             -- 구간 시작 (이상)
                          price_to(numeric, nullable),     -- 구간 끝 (미만, null=상한없음)
                          rate(numeric),                   -- 상한 요율 (예: 0.005 = 0.5%)
                          max_amount(numeric, nullable),   -- 한도액 (해당 구간)
                          effective_from(date),            -- 적용 시작일
                          created_by(FK → users)

-- 거래 사전 고지 체크리스트
-- 거래 등록 시 type(매매/임대차)·role에 맞는 기본 항목 자동 생성, 추가·삭제 가능
-- notify_method: 고지 방법 기록 (구두/문자/이메일/기타) — "안 알려줬다" 분쟁 방지
-- 매매 기본 항목 예시:
--   [매도인] 관리비 정산(전기·가스·수도·인터넷), 재산세 납부 확인,
--            담보대출 상환·근저당 말소 준비, 이사 일정·열쇠 인도 준비
--   [매수인] 취득세 납부 기한(잔금일+60일), 소유권이전등기 신청, 거래 신고(계약일+30일)
-- 임대차 기본 항목 예시:
--   [임대인] 이전 임차인 관리비·공과금 정산 요청, 시설 점검 일정, 보증금 반환 준비
--   [임차인] 관리비·공과금 정산, 원상복구 이행, 짐 반출 확인
transaction_checklists: id(UUID), transaction_id(FK),
                        target_role(매도인/매수인/임대인/임차인),
                        item(text),                    -- 안내 항목명
                        is_completed(boolean, default false),
                        completed_at(timestamp, nullable),
                        notify_method(text, nullable),  -- 구두/문자/이메일/기타
                        note(text, nullable),           -- 추가 메모
                        sort_order(integer)

-- 진단 결과 캐시 (Quick Check 또는 전체 진단 리포트 실행 시 핵심 위험 플래그 저장)
-- 리스트·요약 화면에서 실시간 API 호출 없이 저장된 값으로 즉시 표시
-- risk_level: 없음(플래그 없음) / 주의(1개 이상) / 위험(등기 이상·위반건축물 등 중대 항목)
-- diagnosed_at 기준으로 "N일 전 진단" 표시, 오래된 경우 재진단 안내
-- diagnosed_by: 사용자가 직접 실행한 경우 해당 user_id, 시스템 자동실행(매물 등록 트리거)인 경우 null
-- ─── 진단 변경 알림 전략 ────────────────────────────────────────────────────────
-- notify_diagnosis_change_enabled 알림 발송을 위해 Quick Check/재진단 실행 시 다음 절차를 따른다:
--   1. 저장 전 현재 플래그 값 조회 (SELECT * FROM property_diagnostics WHERE property_id = ?)
--   2. 새 진단 결과와 비교하여 플래그 변경 여부 확인
--   3. 변경된 플래그가 있으면 notifications 레코드 생성 (type='진단변경') 후 저장
-- 이 방식으로 단일 최신 레코드를 유지하면서 변경 감지가 가능하다.
property_diagnostics: id(UUID), property_id(FK, UNIQUE), -- 주소지당 1건 (최신 덮어쓰기)
                      -- 위험 플래그 (boolean)
                      has_violation_building(boolean, default false),  -- 위반건축물
                      has_mortgage(boolean, default false),            -- 근저당권
                      has_seizure(boolean, default false),             -- 압류·가압류
                      has_auction(boolean, default false),             -- 경매개시결정
                      has_injunction(boolean, default false),          -- 처분금지가처분
                      has_trust(boolean, default false),               -- 신탁
                      has_lease_registration(boolean, default false),  -- 임차권등기명령
                      -- 규제지역 플래그 (boolean) — 02_기능1 진단 항목 A 전체 커버
                      is_land_transaction_zone(boolean, default false),-- 토지거래허가구역
                      is_speculation_zone(boolean, default false),     -- 투기과열지구
                      is_adjustment_zone(boolean, default false),      -- 조정대상지역
                      is_redevelopment_zone(boolean, default false),   -- 재개발·재건축 구역
                      -- 종합
                      risk_level(없음/주의/위험),
                      diagnosed_at(timestamp),
                      diagnosed_by(FK → users, nullable) -- null = 시스템 자동실행

-- 파일 첨부 (범용 — disputes·memos·transactions·납부 단계 공용)
-- entity_type + entity_id 조합으로 어떤 엔티티에도 첨부 가능
-- 실제 파일은 Supabase Storage에 저장, file_url은 Storage 경로
-- 지원 형식:
--   이미지 (PNG·JPG·HEIC) — 문자·카톡 캡처 스크린샷
--   오디오 (MP3·M4A·WAV·AAC) — 통화·현장 음성 녹음
--   문서 (PDF·HWP) — 계약서·내용증명·합의서·이체확인증 등
-- entity_type 별 주요 용도:
--   transaction         → 계약서 파일 (계약 전체에 귀속)
--   transaction_payment → 이체확인증·영수증 (개별 납부 단계에 귀속)
--   dispute             → 증거 파일 (분쟁 이력에 귀속)

--   checklist           → 정산 영수증·확인서 (사전 고지 체크리스트에 귀속)
--   maintenance         → 수리·교체 사진, 견적서, 영수증 (시설 관리 이력에 귀속)
attachments: id(UUID),
             entity_type(transaction/transaction_payment/dispute/memo/checklist/maintenance),
             entity_id(UUID),                        -- 연결 대상 PK
             file_name(text),                        -- 원본 파일명
             file_url(text),                         -- Supabase Storage 경로
             file_type(text),                        -- MIME type
             file_size(integer),                     -- bytes
             uploaded_by(FK → users),
             created_at(timestamp)

-- 알림 (거래 기한 / 일정 D-1 / 규제지역 변경 / 대납 미회수 / 수수료 미수령 등 통합 관리)
-- 모든 알림은 기본 활성. 사용자가 settings에서 유형별로 비활성 가능 (users.settings.notify_* 참고)
-- FK 연결 방식: 알림 유형에 따라 해당 FK 하나 이상 설정, 나머지는 null
--   transaction_id : 거래 기한 알림 (신고기한/계약만료/갱신청구권), 수수료 미수령 알림
--   schedule_id    : 일정 D-1 알림 (사전미팅·계약·잔금)
--   property_id    : 규제지역 변경 알림, 진단 결과 변경 알림
--   maintenance_id : 대납 미회수 알림 (property_maintenance.office_recovery_status 미완료)
-- is_read: 읽음 처리 (대시보드 "오늘의 알림"에서 읽음/안읽음 구분)
-- sent_at: 이메일·SMS 발송 완료 시각 (null = 서비스 내 알림만, 미발송)
-- type 값:
--   거래신고기한   : 부동산 거래 신고 기한 (계약일+30일) D-7/D-3/D-1
--   계약만료       : 임대차 계약 만료 D-90/D-60
--   갱신청구권     : 갱신청구권 행사 기한 (종료일 2~6개월 전)
--   일정           : 일정 D-1 알림 (계약·잔금·사전미팅 등)
--   규제지역변경   : 규제지역 DB 변경으로 담당 매물이 새로 포함됨
--   진단변경       : Quick Check/전체 진단 재실행 후 위험 항목 신규 발생 또는 해소
--   대납미회수     : 사무소 대납 후 N일 경과, 회수 미완료
--   수수료미수령   : 잔금완료 후 N일 경과, commission_is_paid=false
--   기타           : 위 유형에 해당하지 않는 알림
notifications: id(UUID),
               transaction_id(FK, nullable),   -- 거래 기한·수수료 미수령 알림
               schedule_id(FK, nullable),       -- 일정 D-1 알림
               property_id(FK, nullable),       -- 규제지역 변경·진단 변경 알림
               maintenance_id(FK → property_maintenance, nullable), -- 대납 미회수 알림
               user_id(FK),                     -- 수신자 (담당 구성원 or admin)
               type(거래신고기한/계약만료/갱신청구권/일정/규제지역변경/진단변경/대납미회수/수수료미수령/기타),
               due_date(date),
               is_read(boolean, default false),
               sent_at(timestamp, nullable),    -- null = 서비스 내 알림만 (이메일·SMS 미발송)
               message(text)

-- 인물 주의 태그 요약 (people 테이블에서 직접 집계 가능하나, 성능을 위해 별도 관리)
-- warning 메모가 1건 이상이면 인물 검색 결과·상세에 주의 배지 표시
-- (실제 구현은 memos 테이블 count로 처리, 별도 테이블 불필요)

-- DB 백업 이력 (GitHub 커밋 히스토리 스타일 복구 UI용)
-- type별 자동 코멘트 생성:
--   daily         → "일별 정기 백업"
--   monthly       → "월별 정기 백업"
--   pre_sync      → "구글 시트 동기화 전 스냅샷 · N건 변경 감지"

--   manual        → "수동 백업 · {사용자명}"
-- snapshot_path: Supabase Storage 경로 (실제 백업 파일)
-- row_count: 백업 시점 매물 수 (UI에서 규모 표시용)
backups: id(UUID),
         type(daily/monthly/pre_sync/pre_import/pre_collect/pre_recovery/manual),

         snapshot_path(text),        -- Supabase Storage 경로
         size_bytes(integer),        -- 백업 파일 크기
         row_count(integer),         -- 백업 시점 properties 행 수
         created_at(timestamp),
         created_by(text)            -- 'system' or user.이름

-- 구글 시트 동기화 변경 로그
-- 매 동기화마다 변경 내역을 기록 → 감사 추적 + 선택적 롤백 근거
-- action: inserted(신규) / updated(수정) / flagged_deleted(시트에서 삭제 감지, 자동 삭제 안 함)
-- backup_id: 해당 동기화 직전에 생성된 백업 FK
sync_logs: id(UUID), synced_at(timestamp), sheet_url(text),
           action(inserted/updated/flagged_deleted),
           property_id(FK, nullable), row_index(integer),
           before_data(JSONB, nullable),   -- 변경 전 값 (updated/flagged_deleted 시)
           after_data(JSONB, nullable),    -- 변경 후 값 (inserted/updated 시)
           backup_id(FK → backups),        -- 해당 동기화 직전 백업
           created_by(text, default 'system')

-- AI 질의응답용 문서
-- embedding: vector(1024) — Cohere-embed-v3-multilingual 출력 차원
documents: id(UUID), type(law/case/press/notice/manual), title, content,
           source, source_date, embedding(vector(1024)), created_at
```

## RLS (Row Level Security) 정책

### MVP — 단일 사무소 (Single-Tenant)

같은 Supabase 프로젝트 = 같은 사무소. 별도 offices 테이블 없이 시작.

```sql
-- 모든 테이블에 동일 적용: 로그인한 사용자만 접근 가능
CREATE POLICY "authenticated_only" ON {table_name}
  USING (auth.uid() IS NOT NULL);
```

- `users` 테이블에 `is_admin(boolean, default false)` 추가 (admin 전용 기능 분기용)
- admin 전용 API Route에서 `SELECT is_admin FROM users WHERE id = auth.uid()` 체크

## Mock 데이터 전략

API 키 발급 전 또는 API 다운 시 개발이 중단되지 않도록 Mock 응답을 준비.

```typescript
// 환경변수 NEXT_PUBLIC_USE_MOCK_API=true 시 실제 API 대신 Mock 반환
// lib/apis/building.ts 예시
const USE_MOCK = process.env.NEXT_PUBLIC_USE_MOCK_API === 'true'

export async function fetchBuilding(address: string) {
  if (USE_MOCK) {
    return import('./__mocks__/building.json')
  }
  // 실제 API 호출
}
```

Mock 파일 위치: `lib/apis/__mocks__/` (위 폴더 구조 참고)
