# 부동산 AI 어시스턴트 서비스 — 최종 개발 계획서 (v3)

## Context

공인중개사가 부동산 정책·법률·판례를 쉽게 검색하고, 부동산 권리관계 분석 리포트를 받는 등 부동산 관련 모든 업무에 AI 도움을 받을 수 있는 서비스를 개발한다. 개발자가 아닌 사용자가 Cursor + Claude Code 바이브 코딩으로 직접 구축한다.

**AI 모델 전략**: Anthropic Claude API 대신 **GitHub Models** (무료)를 사용한다. Phase 4 AI 기능이 예산 제약 없이 즉시 구현 가능하다.

**문서 구조 원칙**: 상세 명세는 `E:\real_estate_AI\docs\` 폴더의 .md 파일이 단일 정보 소스(Source of Truth)다. 이 계획서는 진행 전략과 개발 순서에 집중한다.

## GitHub Models AI 스택

> **무료 API**: GitHub Personal Access Token으로 즉시 사용. 별도 결제 없음.
> **Base URL**: `https://models.inference.ai.azure.com`
> **SDK**: `openai` npm 패키지 + `baseURL` 오버라이드 (OpenAI 호환 API)

| 용도 | 모델명 | 이유 |
|---|---|---|
| AI 질의응답 (RAG Chat) | `gpt-4o` | 한국어 법률 문서 이해 최상, 긴 컨텍스트 |
| 가벼운 요약/분류 | `gpt-4o-mini` | 비용 효율 (간단한 태스크) |
| 임베딩 (RAG 벡터화) | `Cohere-embed-v3-multilingual` | 다국어 명시 지원, 한국어 법령 임베딩 최적 |

**환경변수**: `.env.local`에 `GITHUB_TOKEN=github_pat_...` 추가

```typescript
// lib/github-ai.ts — AI 클라이언트 초기화
import OpenAI from 'openai'

export const ai = new OpenAI({
  baseURL: 'https://models.inference.ai.azure.com',
  apiKey: process.env.GITHUB_TOKEN,
})

// 채팅: ai.chat.completions.create({ model: 'gpt-4o', ... })
// 임베딩: ai.embeddings.create({ model: 'Cohere-embed-v3-multilingual', ... })
```

## Gap Analysis — 논리적 누락 보완

> `docs/05_기술스택.md`와 `docs/06_개발로드맵.md`에 반영이 필요한 항목.

### 🔴 P1 — 즉시 보완 필요

#### 1. 사무소(Office) 테넌트 전략 부재
- **현황**: `users.사무소명(text)`으로 사무소 구분 중. 사무소명이 변경되면 RLS 데이터 격리가 깨짐.
- **보완 방향**: MVP에서는 단일 사무소(single-tenant)로 단순화. `users` 테이블에 `is_admin(boolean)` 추가, 별도 offices 테이블 없이 시작.
- **RLS 정책 전략**:
  - MVP: 모든 테이블에 `auth.uid() IS NOT NULL` RLS만 적용 (같은 Supabase 프로젝트 = 같은 사무소)
  - 추후 멀티테넌트 필요 시 `users.office_id FK → offices` 추가 마이그레이션
- **반영 파일**: `docs/05_기술스택.md` 하단에 RLS 정책 섹션 추가

#### 2. 구성원 초대 플로우 미정
- **현황**: "이메일 초대"라고만 명시, 실제 플로우 없음.
- **보완**: Supabase Admin API의 `inviteUserByEmail()` 사용
  - admin이 이메일 입력 → Supabase가 초대 링크 이메일 발송 → 수신자 링크 클릭 → 비밀번호 설정 페이지 → 저장 시 `users` 테이블 레코드 자동 생성
  - 초대 후 역할(admin/member/assistant) 지정은 admin 전용 설정 화면에서 처리
- **반영 파일**: `docs/06_개발로드맵.md` Phase 3-C에 초대 플로우 상세 추가

#### 3. 소단위 개발 계획 부재 (사용자 명시 요청)
- 현재 계획은 Phase 단위로 너무 커서 중간 점검이 어려움.
- 아래 "소단위 개발 계획" 섹션에 Unit 단위 분해 명세.

#### 4. Mock/Seed 데이터 전략 부재
- **현황**: API 키 발급 전 또는 공공 API 다운 시 개발 중단 위험.
- **보완**: `lib/apis/__mocks__/` 폴더에 플랫폼별 Mock 응답 JSON 파일 준비
  - 환경변수 `NEXT_PUBLIC_USE_MOCK_API=true` 시 실제 API 대신 Mock 파일 반환
  - 개발 초기에는 Mock으로 UI 완성 → API 키 준비 후 실제 연동으로 전환
- **반영 파일**: `docs/05_기술스택.md`에 Mock 전략 섹션 추가

### 🟡 P2 — 구현 시 반드시 고려

#### 5. 등기정보광장 API 일일 한도 관리
- **현황**: 하루 1,000건 한도. Quick Check 자동실행이 신규 등록마다 실행되면 대규모 가져오기 시 초과 위험.
- **보완**: `lib/apis/registry.ts`에 한도 카운터 추가
  - Supabase DB에 `api_usage` 테이블 또는 간단히 Supabase KV(Edge Config)로 일별 사용 건수 추적
  - 한도 근접(900건) 시 이후 Quick Check는 스킵 + admin에게 알림
  - 구글 시트 일괄 가져오기 시 800건/일 분산 예약 로직 이미 `06_개발로드맵.md` 3-E에 있음 (유지)

#### 6. 공공 API 에러 처리 전략 부재
- **현황**: API 실패 시 UI 처리 방법 없음.
- **보완 원칙**: Graceful Degradation
  - 각 API 섹션별 독립 로딩: 하나 실패해도 나머지 섹션은 표시
  - 실패 섹션에 "현재 조회 불가 (잠시 후 재시도)" 메시지 표시
  - 전체 진단 불가 시 Quick Check 결과라도 표시
  - API 키 미설정(`undefined`) 시 개발 경고 로그 + 해당 섹션 "API 키 미설정" 표시

#### 7. 토지거래허가구역 폴리곤 DB 초기 데이터 미정
- **현황**: "자체 DB 구축(폴리곤 매핑)"이라고만 되어 있고 실제 데이터 확보 방법 없음.
- **보완**: 
  - 서울시 열린데이터광장(data.seoul.go.kr)에서 토지거래허가구역 GeoJSON 다운로드
  - PostGIS(`st_contains`) 또는 ray casting 알고리즘으로 좌표 포함 여부 판별
  - MVP에서는 GeoJSON을 정적 파일(`/data/land_transaction_zones.json`)로 관리, 추후 DB 테이블 이전
  - 반드시 Phase 2에서 실제 데이터 확보 후 구현

## DEFERRED 코드 주석 전략

복잡하거나 나중에 구현할 기능은 미리 작성하되 주석 처리. 아래 형식으로 통일:

```typescript
// ============================================================
// [DEFERRED] GitHub Models — AI 진단 종합 의견 생성
// Phase: 4 (U4-3 구현 시 활성화)
// 모델: gpt-4o (GitHub Models 무료)
// 활성화 방법:
//   1. GITHUB_TOKEN 환경변수 확인
//   2. 아래 주석 해제
//   3. lib/github-ai.ts의 generateDiagnosisOpinion() 연결 확인
// ============================================================
```

**주석 처리 대상 파일:**
- `lib/github-ai.ts` — GitHub Models 클라이언트 (AI 진단 의견, 맞춤 특약 생성, RAG)
- `lib/rag.ts` — RAG 질의응답 엔진 (Phase 4 U4-2까지 주석 처리)
- `lib/codef.ts` — CODEF 등기부 풀파싱 (유료 서비스, 별도 계약 필요)
- `lib/solapi.ts` — SMS 발송 (솔라피, 건당 과금) — Phase 3 외부 알림 구현 시 주석 해제
- `app/api/diagnosis/ai/route.ts` — AI 의견 생성 API 라우트
- `app/api/chat/route.ts` — AI 질의응답 엔드포인트

> ⚠️ `lib/claude.ts` 파일은 생성하지 않음. 모든 AI 기능은 `lib/github-ai.ts`로 통합.
